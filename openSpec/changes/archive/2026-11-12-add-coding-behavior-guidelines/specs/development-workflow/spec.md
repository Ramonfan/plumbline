## ADDED Requirements

### Requirement: 编码行为必须控制假设、复杂度和改动范围
执行者在修改实现前 MUST 明确影响方案的关键假设；多种解释会影响已确认契约或验收口径时必须先确认，不影响任何已确认契约或验收口径时 MUST 列出假设并继续，不得静默选择。实现 MUST 采用满足当前需求的最小方案，不引入未被要求的抽象、配置项、扩展点或未来能力；安全、权限、异步、迁移等风险明确要求的失败、取消、幂等和释放路径不属于过度设计。

执行者 MUST 只修改当前 change 授权范围内的代码和文档，不顺手重构、格式化、修改注释或整理无关内容。本次改动产生的未使用导入、变量、函数或文件 MUST 清理；既有死代码 MUST 只记录在当前 change 的残留风险或交付记录后续事项中，不得擅自删除。每个改动簇或逻辑单元 MUST 能追溯到当前 task 或已确认的 change 范围；生成产物、锁文件和工具强制的格式变更可以保留，但 MUST 说明来源、范围和验证方式，并仍须遵守工作区保护对生成产物和锁文件的授权要求。

任务 MUST 以可验证目标表达；完成声明 MUST 引用覆盖当前版本的实际检查、测试或其他证据，不得用主观判断代替。

#### Scenario: 需求存在多种解释
- **WHEN** 任务目标、输入范围、输出位置或成功标准存在多个合理解释
- **THEN** 影响已确认契约或验收口径时必须先请求用户确认；不影响任何已确认契约或验收口径时必须列出假设并继续，不得静默选择一种实现

#### Scenario: 发现更简单的实现路径
- **WHEN** 当前方案需要新增抽象、配置项或扩展点，而更小的方案已经满足当前需求
- **THEN** 执行者必须先说明更简方案，不引入未被要求的复杂度

#### Scenario: 目标附近存在无关代码
- **WHEN** 修改目标文件时发现相邻代码、注释、格式或无关文件有可改进空间
- **THEN** 本次改动不得顺手整理，只能记录或另行提出，除非用户明确授权扩大范围

#### Scenario: 本次改动产生孤儿代码
- **WHEN** 当前改动导致导入、变量、函数或文件不再被使用
- **THEN** 执行者必须清理本次改动产生的孤儿代码；现有死代码只能记录在当前 change 的残留风险或后续事项中，不得擅自删除

#### Scenario: 风险要求防御性处理
- **WHEN** 安全、权限、异步、数据迁移或核心链路要求失败、取消、重复进入、幂等或释放路径
- **THEN** 这些处理必须保留，不得以“最小实现”为由删除

#### Scenario: 任务完成声明
- **WHEN** 执行者准备声明任务完成、修复或通过
- **THEN** 必须给出可验证的成功标准，并引用覆盖当前版本的实际命令、测试或其他证据

#### Scenario: 生成产物或工具强制变更
- **WHEN** 当前任务需要更新生成产物、锁文件，或格式化工具会改动目标文件
- **THEN** 允许保留这些变更，但必须说明来源、范围和验证方式，不得用其掩盖无关改动
