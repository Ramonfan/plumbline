## Why

当前工作流已经具备预览、空目标安装、冲突拒绝和统一校验，但验证脚本写死 `/private/tmp`，安装器没有拒绝目标目录内部的符号链接父路径，冲突零写入测试也未覆盖“部分冲突的空目标”。同时，消费项目虽被要求记录接入基线，模板包自身却没有可复制、可比较的版本标识。这些缺口会削弱跨平台复用、安全边界和后续升级追溯。

## What Changes

- 为模板包增加机器可读的工作流基线文件，并随安全安装复制到目标项目。
- 将验证临时目录改为使用环境提供的临时目录或通用回退目录，不依赖 `/private/tmp`。
- 在安装写入前检查目标文件的既有父路径；发现符号链接或非目录父路径时，报告不安全路径并零写入退出。
- 扩展安装验证矩阵，覆盖部分冲突目标、完整冲突清单、确定的退出状态、目录与文件零新增，以及符号链接父路径拒绝。
- 同步安装说明、项目配置模板、根项目说明、验证清单和 `CHANGELOG.md`，说明版本基线的读取与升级比较方式。
- 使用 Archify 生成并验证当前工作流图，展示任务分级、三个门禁、OpenSpec 工件、实施验证、验收归档和消费项目回流。
- 不增加覆盖安装、自动升级、自动变量替换、事务式回滚、Git 初始化或跨项目自动同步能力。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `portable-project-workflow`：加强安全安装的路径边界与零写入验收，并要求模板提供可识别、可复制的工作流版本基线和可移植的统一验证入口。

## Impact

- 受影响文件：`scripts/install.sh`、`scripts/verify.sh`、`templates/project-workflow/` 下的基线文件与安装文档、根 `README.md`、`PROJECT_PROFILE.md`、`CHANGELOG.md`，本 change 的 delta spec、design 和 tasks，以及独立 Archify 可视化产物。
- 安装映射新增一个目标文件；已有消费项目不会被自动修改，后续人工升级时需要比较并决定是否补入该文件。
- `install.sh` 现有参数保持不变；安全路径拒绝属于保护性收紧，不改变无冲突普通目录的成功行为。
- 不新增第三方依赖，不初始化 Git，不执行发布。

## 需求门禁结论

- 任务等级：L2。
- 目标：补齐跨平台验证、安装路径边界、严格零写入证据和版本基线识别。
- 非目标：覆盖安装、自动升级、失败后的事务回滚、自动发布和跨项目自动覆盖。
- 验收口径：统一校验在当前环境通过；自定义临时目录可用；普通空目标安装成功；部分冲突和符号链接父路径均在写入前失败且目标内外零新增；安装结果包含可解析的基线文件；两份长期主规格 strict validation 通过。
- 用户已同意按该方向建立 L2 change；实际修改模板和脚本仍需通过方案门禁。
