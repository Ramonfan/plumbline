# Superpowers 实施阶段检查清单

本清单只用于方案门禁通过后的开发执行。需求、行为规格、技术设计、任务状态、验收证据和归档由 OpenSpec 管理；本文件不得成为第二套事实源。

项目命令、仓库边界、运行环境和人工验收方式以根目录 `PROJECT_PROFILE.md` 为准。

## 测试与测试驱动开发

- [ ] 已从当前 OpenSpec specs 和 tasks 提取本次可验证行为。
- [ ] 已按任务风险和方案门禁结论决定使用现有测试、补充专项测试、采用 TDD 或使用替代验证。
- [ ] 采用 TDD 时，已先观察目标测试失败，并确认失败原因与需求一致。
- [ ] 实现只覆盖当前失败行为，没有扩大需求。
- [ ] 测试通过后，已确认没有通过放宽断言、跳过用例或吞掉错误制造假成功。
- [ ] 项目缺少测试基础时，已在 OpenSpec tasks 记录替代验证、局限和人工验收项。
- [ ] 验证结果已回写当前 task，而不是只保留在本清单中。

## 编码行为与范围控制

- [ ] 已记录影响实现的关键假设；多种解释会影响已确认契约或验收口径时已确认，不影响任何已确认契约或验收口径时已列出假设并继续。
- [ ] 没有引入当前 task 未要求的抽象、配置项、扩展点或未来能力。
- [ ] 没有顺手重构、格式化、修改注释或整理无关代码；风格与邻近代码一致。
- [ ] 仅删除本次改动产生的孤儿导入、变量、函数或文件；既有死代码仅记录在残留风险或后续事项中。
- [ ] 每个改动簇或逻辑单元都能追溯到当前 OpenSpec task 或已确认的 change 范围；生成产物、锁文件和工具强制的格式变更已说明来源、范围和验证方式，并已确认授权要求。
- [ ] task 的成功标准可验证，并已用实际命令、测试或其他检查验证，而非主观判断。
- [ ] 安全、权限、异步、迁移等风险要求的失败、取消、幂等、重试和释放路径未被误删为“过度设计”。

## 系统化调试

- [ ] 已记录用户现象、复现条件、时间点、环境、账号或业务标识。
- [ ] 已先收集日志、状态和代码链路证据，没有用假设代替根因。
- [ ] 已对比正常与异常路径、变更前后、不同环境或不同数据组合。
- [ ] 已定位首次偏离预期的位置，而不是只修复最后呈现的错误。
- [ ] 已验证候选根因可以解释全部关键现象，并记录已排除项。
- [ ] 修复范围、兼容边界、失败路径和回归矩阵已回写 OpenSpec design/tasks。

## 代码审查

- [ ] 审查方式与任务等级匹配：L1 默认本地审查，L2 按风险，复杂异步、安全权限、公共接口和 L3 使用独立审查。
- [ ] 已按业务正确性、兼容、安全、竞态、循环、性能、资源和生命周期顺序审查。
- [ ] 已检查输入校验、错误处理、权限、敏感数据、日志和失败降级。
- [ ] 已检查接口、数据契约、持久化、缓存、消息和跨模块字段的一致性。
- [ ] 已检查异步取消、过期结果、重复进入、重试、幂等和释放路径。
- [ ] UI 或交互任务已检查状态切换、动态内容、复用、可访问性、主题和小尺寸环境。
- [ ] 已分别检查实际受影响仓库，没有使用工作区根目录代替多仓结论。
- [ ] 未提交改动、暂存区和无关文件与实施前基线一致或已明确记录。
- [ ] 审查发现已修复或记录为明确残留风险，并回写当前 change。

## 完成前验证

- [ ] 已重新读取 OpenSpec tasks，逐项核对实现与验收标准，没有遗漏或静默缩小范围。
- [ ] 验证证据覆盖当前源码、依赖和环境版本；相关变化后已重新验证。
- [ ] 已运行 `PROJECT_PROFILE.md` 定义的最窄格式、静态、类型、测试或构建命令。
- [ ] 修复编译、构建、迁移或部署错误后，已执行对应真实命令，未用语法检查替代。
- [ ] 多仓任务已分别执行状态、差异和格式检查，并记录各仓结果。
- [ ] 路由、缓存、权限、异步、监听、定时器、后台任务和资源句柄已覆盖失败、取消、重复进入和释放路径。
- [ ] 人工无法自动化的业务、交互、视觉、设备、浏览器或环境项仍保留为未完成验收任务。
- [ ] 验证命令、退出码、结果、未执行原因、环境版本、无关脏改和残留风险已回写 OpenSpec。
- [ ] 长命令完整日志已保存，只提取必要错误和最终摘要，没有连续短轮询。
- [ ] 已运行当前 change 的 OpenSpec strict validation。
- [ ] 用户尚未完成交付验收时，没有勾选最终验收任务，也没有归档。

## 交付前事实核对

- [ ] 准备声明“完成、修复、通过”前，已在当前轮次运行能够证明该声明的命令并检查完整结果。
- [ ] 测试通过声明包含实际用例数或失败数；构建通过声明包含退出码和成功标志。
- [ ] 静态检查、单元测试、构建和人工验收的证明范围已明确区分，未互相替代。
- [ ] 未使用“应该、看起来、理论上”代替可复核证据。
- [ ] 最终交付摘要与 OpenSpec tasks、实际文件差异和验证结果一致。
